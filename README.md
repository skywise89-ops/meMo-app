# meMo

두 사람을 위한 Firebase 기반 PWA 채팅 앱이다. 별도 빌드 없이 정적 호스팅에서 실행한다.

## 주요 구성

- `index.html`: UI, Firebase Auth/Realtime Database/Storage 연동, 채팅·앨범·좋아요·검색·버킷·보관함
- `app-core.js`: 검색 정규화, 앨범 날짜, 영상 용량 검증 등 테스트 가능한 순수 로직
- `firebase-messaging-sw.js`: FCM 백그라운드 알림과 중복 방지
- `manifest.json`: PWA 설치 정보
- `tests/app.test.mjs`: JavaScript 구문, DOM ID, 핵심 기능 배선 정적 검사
- `functions/`: 관리자 앨범 삭제·복구, 음성 메시지 생성, 7일 만료 정리
- `database.rules.json`, `storage.rules`: 두 계정 전용 서버 권한과 파일 크기 검증

## Firebase 배포

운영 규칙을 먼저 백업한 뒤 실행한다.

```bash
npx firebase-tools@15.25.1 deploy --only database,storage --project memo-e366f
npx firebase-tools@15.25.1 deploy --only functions:translateText,functions:fillMissingTranslation,functions:deleteAlbumMedia,functions:restoreAlbumMedia,functions:createVoiceMessage,functions:purgeExpiredMedia,functions:cleanupOrphanVoiceUploads --project memo-e366f
```

기존 `sendPushOnMessage`는 별도 운영 자산이다. 함수 전체 배포는 이를 삭제 후보로 만들 수 있으므로 위 함수 목록을 유지한다. 음성 메시지 알림 문구가 필요하면 발송 서버에서 `type: audio`를 `🎙️ 음성 메시지`로 처리해야 한다.

## v4.4 비용·성능 개선

- 방 입장마다 세션을 구분하고 로그아웃/계정 변경에서 RTDB 구독·이벤트·타이머를 해제한다. 이전 세션의 비동기 응답은 새 화면을 갱신하지 않는다. 백그라운드 전환이나 일시적인 오프라인만으로 방 구독을 끊지 않는다.
- 앨범은 키 기반으로 변경된 카드만 갱신한다. 전체 기간·유형·즐겨찾기 필터와 전체 개수, 최신순 날짜 묶음, 스크롤 위치를 유지한다. 최신 일부만 검색/필터링하는 범위 축소형 페이지 처리는 하지 않는다.
- 영상은 채팅 안에서 첫 재생 클릭 때만 원본을 연결한다. 앨범 뷰어도 기존처럼 카드 클릭 한 번으로 재생을 시도하며 실패 시 재시도 버튼을 표시한다.
- 새 영상 썸네일은 로컬 Blob에서 업로드와 병렬로 최대 3초 동안 생성하고 JPEG 16KiB 이하로 제한한다. 실패해도 원본 업로드는 계속한다. 별도 Storage 썸네일 파일이나 대량 과거 파일 재다운로드는 만들지 않는다.
- 기존 영상 미리보기는 실제 화면에 보일 때만 메타데이터/프레임을 불러오고 작은 프레임을 세션 메모리에서 재사용한다. 과거 영상도 무조건 다운로드 0이 되는 것은 아니다. 세션 프레임은 최대 256개/4MiB이다.
- 검색은 기존 전체 대화 범위, 200개씩 스캔, 최대 300개 표시와 전체 일치 건수를 유지한다. 최신 페이지는 매번 확인하고 과거 페이지는 세션 메모리에서 최대 16MiB/5분 재사용한다. 실시간 변경/삭제/추가 이벤트는 해당 페이지를 무효화한다. 검색 기록은 디스크에 저장하지 않고 로그아웃 때 지운다.
- 서비스워커는 인증 세션이 확인된 클라이언트의 현재 Firebase 버킷 이미지에만 캐시 우선을 적용한다. 파일 2MiB 이하, 전체 32MiB/128개, 24시간 만료이다. 영상/음성/Range/API/DB/인증/HTML 요청은 캐시하지 않는다. CORS 실패 시 기존 요청으로 돌아가 표시를 유지한다.
- 이미지 캐시는 계정별로 분리하고 로그아웃/계정 전환·파일 삭제에서 정리한다. 진행 중 응답이 삭제된 캐시를 다시 쓰는 경쟁 조건도 차단한다. 서비스워커 재시작 후 세션 확인 전에는 네트워크만 사용한다.
- 신규 업로드는 private Cache-Control을 지정한다. 기존 파일 메타데이터·DB 내용·Storage/RTDB 보안 규칙·Cloud Functions·번역·FCM 발송 서버는 변경하지 않는다.

검증: 전체 Node 테스트 및 분리된 브라우저 픽스처의 목록/검색/재로그인/영상 재생 검사. 실제 절감률은 운영 사용량을 비교해야 하며 정량 절감을 보장하지 않는다. iOS 설치형 PWA는 기기별 추가 확인을 권장한다.
